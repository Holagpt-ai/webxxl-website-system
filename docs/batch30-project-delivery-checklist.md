# Staff project delivery checklist (WebXXL)

Reusable handoff for website projects after lead conversion or admin onboarding.

## Development completion

- [ ] Project created from **Standard Business Website** template (or documented exception).
- [ ] Milestones and tasks reflect actual scope; weights total 100%.
- [ ] Customer dependencies initialized and still accurate.
- [ ] Website preview registered via admin project panel (generic provider form).
- [ ] Each new deployment has its own **PENDING** version approval.

## Customer review

- [ ] Customer can access project in portal (membership active or invitation pending with accurate status).
- [ ] Current immutable preview version visible; prior versions in approval history.
- [ ] Owner review package completed where applicable (ABMED and future accounts with catalog).
- [ ] Revision requests tied to correct deployment version.

## Launch readiness (not automatic delivery)

- [ ] Customer dependencies addressed or explicitly waived by staff.
- [ ] Version-specific website approval recorded when customer signs off on a deployment.
- [ ] **Separate** domain / WordPress cutover authorization — not implied by preview approval.
- [ ] Resend / transactional email configured before relying on portal invitations or contact delivery.

## Marking delivered

Only mark project **COMPLETED** when agreed deliverables are live or accepted per contract — not when preview alone is READY or a single milestone is done.
